# Конвенции разметки

## 1. Frontmatter вершины

```yaml
---
type: block                     # chapter | section | heading | block — без него вершины нет
id: Ch01-S02-H03-B01            # уникальный код; дублируется в aliases
name: "Norm identity 1.2.3b"    # 1-я строка подписи (EN)
name_zh: "范数恒等式 1.2.3b"      # 2-я строка подписи (перевод)
aliases: ["Ch01-S02-H03-B01"]   # поиск и автодополнение по id; ссылки всё равно пишите по имени файла
status: placeholder             # placeholder → заглушка; замените на real | draft | done
parent: Ch01-S02-H03            # код родителя (для структурных рёбер)
chapter: Ch01                   # для фильтра по главе в представлении графа
refs: 4                         # опц.: число входящих ссылок; проставляет команда плагина
size: 1.4                       # опц.: множитель размера вершины (или "22px" — размер в px)
color: "#ff7a6b"                # опц.: свой цвет блока; без него цвет главы, к которой она относится
caption: "[[Ch01-S02 — caption]]"  # опц.: заметка сообщения (у вершины любого типа)
cssclasses: ["lg-node", "lg-node--block"]
---
```

Все поля — это обычные свойства Obsidian: правятся в панели **Page properties**
(`Ctrl+;`), и именно их читает плагин. Ключи переименовываются в настройках
`Lecture Graph → Ключ основной подписи / Ключ перевода`.

### 1.1. Поля внешнего вида: `size:`, `color:`, `caption:`

| поле | что делает | примеры |
|---|---|---|
| `size:` | размер **сверх** формулы «радиус = число входящих ссылок»: `1.4` — множитель, `22px` — фиксированный радиус в пикселах. Кегль подписи растёт пропорционально вершине, так что крупная вершина = крупный текст | `size: 2`, `size: 0.6`, `size: 30px` |
| `color:` | цвет вершины. По умолчанию цвета grouped по главам: у главы свой цвет из палитры, а её секции, заголовки и блоки наследуют его — кластер видно целиком. `color:` перебивает наследование для отдельной вершины или целого блока (у блока тот же смысл: «хочу другой цвет») | `color: "#5fd3c4"` |
| `keywords_en:` | ключевые фразы вершины через `;` (работают для любого типа, чаще всего у блоков) — по ним плагин находит вхождения в корпусе `35 - Abstracts` и создаёт связи с секциями и заголовками (см. §7). Ключ `keywords:` принимается как алиас | `keywords_en: "duality gap; adjoint estimate"` |
| `weight:` | суммарное число вхождений фраз по корпусу — вес вершины. Его пишет алгоритм (`Recompute keyword links`), руками его держать незачем; если вес есть, размер вершины считается по нему, а не по числу ссылок | `weight: 9` |
| `caption:` | ссылка на заметку сообщения (папка `45 - Captions`). Её текст показывается пузырьком рядом с вершиной при клике — **у вершины любого типа** (глава, секция, заголовок, блок); если свойства нет, плагин ищет заметку `<id> — caption`. Заметка сообщения — **не** вершина графа: её папка исключена из обхода, а сама она помечена `type: caption` | `caption: "[[Ch01 — caption]]"` |

Все пять полей — обычные свойства: `size` и `color` плагин перечитывает без пересборки (`⟳ Rebuild`
нужен только новым ссылкам), `caption:` создаётся сам кнопкой «+ Создать по шаблону» в пузырьке, а
`keywords_en:` вы заполняете руками и по нему уже работает `Recompute keyword links` (§7), а
`weight:` — результат этого пересчёта. Порода не меняется: `keywords_en` и `weight` не обязательны,
пустое значение означает «вершина без ключевых фраз», и тогда её размер считается по ссылкам. В
демо-курсе фразы собраны у 25% блоков, вес самого тяжёлого — 29 вхождений,
всего рёбер по фразам — 1642, вершин с весом — 186.
Ключи переименовываются в настройках (`Ключ размера вершины`, `Ключ цвета вершины`, `Ключ заметки сообщения`,
`Ключ ключевых фраз`, `Ключ веса вершины`) и в `data.json` (`sizeKey`, `colorKey`, `captionKey`,
`keywordsKey`, `weightKey`).

## 2. Текст секции

Секция содержит заголовки третьего уровня, а сразу под каждым — текст со ссылками:

```markdown
### [[ChXX-SXX-HXX - Adjoint Operator|Adjoint Operator]]

We record three referable statements: [[ChXX-SXX-HXX-B01 - Proposition 1.2.3a|Proposition 1.2.3a]],
[[ChXX-SXX-HXX-B02 - Identity 1.2.3b|Identity 1.2.3b]] and [[ChXX-SXX-HXX-B04 - Estimate 1.2.3d|Estimate 1.2.3d]].

(Имя файла целиком + подпись после `|`: так ссылка резолвится без алиасов, а в тексте остаётся короткой.)
```

Такая ссылка = ребро «секция → блок». Сколько рёбер вошло в вершину — такой она и рисуется.

## 3. Формулы и блоки (важно!)

- Блок-заметка: `$$` **отдельной строкой**, без отступа и без обёртки. Пустые строки до и после обязательны.
- **Не оборачивайте формулы в callout** (`> [!note]`) и не вкладывайте в списки с отступом:
  внутри blockquote рендер `$$…$$` в части тем ломается. Если нужен «рамкой» — делайте рамку
  вокруг *текста*, а формулу оставляйте на верхнем уровне.
- Врезка блока в текст: `![[Ch01-S02-H03-B01 - Proposition 1.2.3a]]` — формулы внутри врезки рендерятся нормально,
  и ребро при этом считается как `embed` (типы ссылок видны в счётчиках после `⟳ Rebuild` и в
данных вершины при клике на неё).
- Inline-формула `$…$` не должна содержать пробелов по краям (`$ x $` может не отрендериться).
- Если блок живёт внутри текста секции, а не отдельным файлом — ставьте якорь
  `^blk-…` отдельной строкой сразу после блока (см. `40 - Templates/T Block inline.md`)
  и включите настройку `Считать инлайн-блоки отдельными вершинами`.

## 4. Ссылки

| зачем | как писать |
|---|---|
| на главу/секцию/заголовок/блок | `[[ChXX-SXX-HXX - Adjoint Operator|Adjoint Operator]]` — имя файла целиком; короткое `[[ChXX-SXX-HXX]]` работает только через `aliases` |
| врезать блок с формулой | `![[ChXX-SXX-HXX-B01 - Proposition 1.2.3a]]` |
| на якорь внутри заметки | `[[#^blk-01-s02-eq1]]` |
| на заголовок внутри заметки | `[[ChXX-SXX-HXX - Adjoint Operator#Blocks]]` |

Ссылки внутри ``` код-блогов и `inline code` ребром не считаются (так ведёт себя Obsidian, так же считает плагин).

Связь между двумя вершинами можно создать прямо из окна графа — **ЛКМ по первой вершине, затем
`Ctrl`+ЛКМ по второй**: плагин дописывает `- [[имя-файла|название]] — added via graph` в раздел
`## Related topics` заметки первой вершины (раздел создаётся при необходимости; регион
`keywords:begin/end` не трогается), граф пересобирается, и дуга рисуется автоматически.
Пометка `added via graph` — чтобы такие строки легко находились: удаление связи = удалить строку.
Подробности — в [[02 Graph — как читать и править]], раздел «Как создать связь между двумя вершинами вручную».

## 5. Переименование и слияние

Файл можно переименовывать: ссылки стоят по полному имени файла, и Obsidian обновляет их сам
(если у вас включено `Settings → Files & Links → Automatically update links`). Не меняйте `id` и `type`.
Слияние двух блоков: оставьте `id` того, на который ссылок больше, а второй превратите в редирект
(`type: block` + `aliases: ["старый-id"]` + одна строка `Merged into [[…]]`).

## 6. Быстрая проверка

`Ctrl+P → Lecture Graph: Write reference counts into note properties` проставит `refs: N`
в каждую вершину, после чего [[Graph Board]] и любой Dataview-запрос смогут сортировку по числу ссылок.
`Ctrl+P → Lecture Graph: Recompute keyword links` пересчитает связи по ключевым фразам (§7): он
допишет их в заметки блоков между маркерами `keywords:begin/end` и обновит `weight:` — повторный
запуск ничего не меняет, так что команду можно держать в привычках после любой правки аннотаций.

## 7. Ключевые фразы: связи и вес вершины из корпуса (реализовано)

Идея: новая вершина создаётся **пустой** — без `parent:` и `chapter:`, только две строки подписи
(`40 - Templates/T Block.md` больше ничего не спрашивает). Связи, вес и цвет ей выдаёт алгоритм
по ключевым фразам. Быстрее всего это делает сам граф: **правый клик по пустому холсту →
`Create node (EN / 中文 / keywords)`** — модалка спрашивает название на английском, перевод на
китайский и список фраз, создаёт заметку в нужной папке и сразу запускает поиск связанных тем
(подробности — в [[02 Graph — как читать и править]], раздел «Как добавить вершину в граф»).

**Как задаётся.** В свойствах блока — фразы на английском через `;`:

```yaml
keywords_en: "compact operator; adjoint estimate"
```

Ключ `keywords:` принимается как алиас (так было подписано в первой заметке про корпус); регистр
и лишние пробелы не важны, дубли убираются, `[[ссылки]]` в списке не нужны — это именно фразы.

**Что ищется.** Точные совпадения (без учёта регистра, целыми словами — `regularization` не
ловит `regularizations`) во всех заметках папки `35 - Abstracts`. Одна такая заметка = одна
секция курса: строка `# …` — имя вершины-секции, дальше текст, потом `## название заголовка`
и текст под ним, и так до конца. Отсюда правило области:

* фраза найдена **в тексте до первого `##`** → связь с вершиной-секцией;
* фраза найдена **внутри региона `## …`** → связь с вершиной-заголовка (`25 - Headings`);
* строка `## Название` самим вхождением не считается (иначе вес рисовало бы форматирование).

Корпус живёт в `35 - Abstracts/ChNN/` — по одной заметке на секцию (`type: abstract`, 36 штук в
демо-курсе). Его генерирует `dev/write_abstracts.py`, но можно писать и руками: правила те же,
фраза обязана встречаться в тексте ровно как подстрока.

**Вес и размер.** `weight` вершины = суммарное число вхождений её фраз по всему корпусу (не число
заметок и не число найденных заголовков). У блоков с фразами именно вес задаёт размер: формула
из §«Размер вершины» та же, только вместо ссылочной степени подставляется `weight` — поэтому
«важность» темы видно, даже если в текст блока никто не сослался.

**Цвет.** Блок красится цветом той главы, чьи секции и заголовки собрали больше всего его
вхождений; при равенстве остаётся своя глава. Свой `color:` (§1.1) перебивает и это правило,
и наследование.

**Ссылки материализуются в заметку.** Чтобы ядро оставалось единственным источником рёбер,
алгоритм не держит связи в своём состоянии, а дописывает их в конец заметки блока:

```markdown
<!-- keywords:begin -->
Связи по `keywords_en` (duality gap) — найдено в аннотациях `35 - Abstracts`. Число после ×
— вес ребра …
- [[Ch04-S01-H01 - Definition Duality Gap|duality gap ×3]] — заголовок `Ch04-S01-H01`, 3 вхождения в корпусе
- [[Ch02-S01 - Setup and Notation|duality gap]] — секция `Ch02-S01`, 1 вхождение в корпусе

**Вес по ключевым фразам: 20 · глава Ch04 (текст до первого `##` — связь с секцией, …)**
<!-- keywords:end -->
```

Всё, что между маркерами, принадлежит алгоритму; всё вокруг — ваше, и оно не трогается байт-в-байт
(формулы, `Used together with:`, `caption:`). Повторный запуск не меняет файл. Число `×N` в
псевдониме — не украшение: ядро строит ребро весом `N`, поэтому «вес в заметке» и «вес в графе»
не могут разойтись.

**Где считать.** В Obsidian — `Ctrl+P → Lecture Graph: Recompute keyword links`; в терминале —
тот же код: `python3 dev/write_abstracts.py` (создаёт корпус) и `node dev/apply_keywords.js
--check` (проверяет, что ссылки в заметках свежие; используется `dev/finalize.py`). Тумблер
`Настройки → Lecture Graph → Ключевые фразы → Считать рёбра по ключевым фразам` выключает
механику целиком: рёбра корпуса исчезают из графа, размер снова считается по ссылкам, цвет — по
структурной главе (в пузырке вершины при этом остаётся список фраз и пометка «счёт выключен»).

**Чего алгоритм не делает.** Связи «блок ↔ блок» остаются ручными (§2) — алгоритм их не порождает;
`parent:`/`chapter:` он не дописывает (иерархию по-прежнему задаёт текст заметки), и в `35 - Abstracts`
вершинами не считает: папка исключена из обхода и в настройках плагина, и во встроенном графе.
